## 三、自动化脚本（避免每只手工拉数据）

### 3.1 已实现的 Python 处理逻辑

已在首批 4 只分析中打通的通用步骤：

```python
# 载入
def load(p): return json.load(open(p, encoding='utf-8'))
lumi = {str(l['Id']): l for l in load('D:/lumiwiki/public/data/internal/Lumi.json')}
skills = {str(s['Id']): s for s in load('.../ActiveSkill.json')}
passives = {str(p['Id']): p for p in load('.../BattlePassive.json')}
buffs = {f"{b['BuffId']}-{b.get('BuffLv',1)}": b for b in load('.../BattleBuff.json')}
keywords = {str(k['Id']): k for k in load('.../BattleKeywordDes.json')}
zh = load('.../zh-CN.json')

# 关键字递归展开
def find_keywords(text):
    kws = {}
    for kid in re.findall(r'<link=(\d+)>', text):
        k = keywords[kid]
        kws[kid] = (tr(k['Name']), tr(k['Des']))
        # 递归展开嵌套 <link>
        for nk_id, nk in find_keywords(kws[kid][1]).items():
            kws.setdefault(nk_id, nk)
    return kws
```

见 [[feedback_skill_desc_keywords]] memory 的完整模板。

### 3.2 需要建的分析脚本

**建议加到 `D:/lumiwiki/scripts/` 下**（跟其他数据处理脚本一起）：

1. **`scripts/analysis/list-unreleased-lumi.mjs`**：diff 对内 vs 对外 Lumi 表，输出新增列表 + 家族分组 + 按 tag 分类
2. **`scripts/analysis/dump-lumi-skills.mjs`**：输入 lumiId 列表，输出每只完整技能/被动/Skill2 池 + **自动展开所有 `<link>` 关键字**（把首批 4 只的 Python 脚本移植到 Node.js）
3. **`scripts/analysis/theoretical-dps.mjs`**：走 [[02 章]] 15 步公式，输入 lumi 面板 + 技能 → 输出理论 DPS 范围
4. **`scripts/analysis/t1-baseline.mjs`**：从 ladder-week*.json 拉最新周的 top10 出场 + top10 高胜作为对标基准

**优先做 1 + 2**（覆盖 80% 手工工作量）；3 + 4 是加分项。

## 七、限制与假设

**这份框架的假设**：
- Lumi 家族的中间形态数值线性衰减（3 形态 = 100%/85%/70% 面板）—— 待验证
- LumiTag=201 是万圣节赛季 —— 待确认
- Skill2 池玩家自选的分布均衡（如果玩家只用一个选项，其他 5 个的分析是废纸）

**不能做的**：
- 精确胜率数字（只有理论区间 ±10%）
- 战斗内节奏 / 换宠时机数据
- 玩家使用体验（好玩 vs 无聊）
